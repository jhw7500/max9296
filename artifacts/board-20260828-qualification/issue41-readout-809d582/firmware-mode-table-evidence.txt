The max9296 driver does not parse sensor-mode tables from the blob. It sends
the bytes through the AP1302 bootdata window starting at 0x8000, wraps the
window every 8192 bytes, and writes 0xffff to 0x6002 to process bootdata.

16-bit pointer view:
  CONF_0=0xAECC
  CONF_1=0xAF10
  CONF_2=0xAF90
  CONF_3=0x0000
  CONF_4=0x0000
  CONF_5=0x0000
  CONF_6=0x0000
  CONF_7=0xA330

AP1302 Register Reference interpretation:
  CONF_0..5 map sensor-mode events 0..5.
  CONF_6 is the sensor-deselect event.
  CONF_7 is the sensor-select event.
Therefore only sensor modes 0, 1, and 2 have mapped configuration tables in
this firmware. Modes 3..5 are null; 6/7 are not readout modes; 8..15 are not
represented by SENSOR0_CONF_0..7.

The mode 1/2 tables both program AR0234 READ_MODE 0x3040=0x3020 and
X/Y_ODD_INC 0x30A2/0x30A6=0x0003. The distinguishing 0x30B0 operations clear
bit 7 in mode 1 and set bit 7 in mode 2. AR0234 Register Reference defines
bit 7 as MONO_CHROME_OPERATION.
